# 已知限制与未验证行为

> **何时读**：判断某个结论可不可信、或想知道什么还没验证时

判断某条结论可不可信之前先看这里。**"未验证"不等于"不会发生"**。

## 已知限制

### 总管会话会不断增长（已有重置/轮换机制）

每次唤醒都把整轮（操作卡 + 事件小节 + 模型工具调用/结果）**追加到同一个会话**，所以它是 7×24 长跑
里唯一会"爆"的东西。因此 `bin/monitor_roll.py`（由 `wake.sh` 每轮先问）按上下文百分比、
唤醒次数与"上次唤醒卡死"三个条件触发：优先 `future session reset` **原地重置历史**，
不可用时才另开新会话并归档旧的。安全约束：**monitor 正在 streaming 时绝不重置/轮换**（会弄丢活回合）、
新建失败则沿用旧 id、连续在途不重复轮换。细节见 [architecture.md](../architecture.md)。

关键认识：**持久记忆在磁盘**（`journal/` `reports/` `.future/memory/`，都不进 git）与仓库里的机制文档
（`docs/` `POLICY.md`），都不在对话历史里——
所以重置/换会话不丢东西；唤醒卡会在开头告诉它先读哪些。

- 依赖本机 **Future Agent 进程**：不可达时 `decide.py` 记 `agent unreachable` 且不唤醒；
  扫描器仍会跑，恢复后自动接上。桌面端关闭不影响扫描，但唤醒需要 agent。
- 二进制被换（重新安装）会影响后续回合；`bin/toolpath.py` 负责解析，别写死路径。

## 设计上做不到的事

- **不能打断正在跑的回合**：禁止 `--steer`、禁止 `session abort`。因此"事后更正"对在跑的会话
  一定迟到（见 `gotcha-send.md`），只能在发送前把边界写清楚。
- **不能批准/拒绝权限**：由确定性脚本 `approvals.py` 负责，回合本身无权改判。
- **不能对外发送**：飞书/邮件/短信/公开发布一律不做（用户不加飞书渠道）。
- **不能改业务仓源码或已安装 skill 来改变自身行为**（那走派工单）。
- **可以改本设施自身**：`POLICY.md` / `bin/config.json` / `prompts/` / `bin/` / `docs/` / `AGENTS.md` /
  守护进程的调度配置（launchd / systemd / 计划任务）都属自我迭代范围（走 worktree + PR + CI）；
  但不因此越过白名单其余各条。

## 会误导人的信号（别当因果用）

- `updatedAtMs` 批量刷新 → 看起来"会话刚活动过"（`gotcha-scan.md`）。
- git 的 author date ≠ committer date → 看起来"更早/更晚发生"（`gotcha-records.md`）。
- 会话自报"我没有 push" → 必须回读 transcript 与 git 核实。
- 自报式护栏（`guard.py record`）→ 会忘记写，所以 `guard.py` 改为**回读 transcript**
  （`observed_sends()`）；`state/sent.jsonl` 只作补充，`guard.py check <id>` 取两者较大值。

## 判据本身的边界（错的是判据，不是结论）

这两条不属某个工具，但它们曾把"正常"判成"故障"，所以放在这里而不是 `gotcha-tools.md`。

- **判"操作是否生效"必须在一个有界窗口内采样**。曾有个"重置是否有效"的判据把读数采在**下一次
  触发阈值时**——那一刻上下文必然已涨回来，于是"有效"永远被判成"无效"，把本来正常的会话换掉了。
  采样时刻要绑定在操作之后的固定窗口内，否则你测的是"效应 + 之后所有的增长"，而增长总会赢。
  **样本要带时间戳**（没有时间戳的样本无法事后追责），判据用三态
  （effective / ineffective / unknown），`unknown` 时先重试而不是直接走兜底。
- **核"最小值"类结论：先要一个显式构造，再谈证明**。一个有清单的上界胜过一段漂亮的论证；
  给不出清单的"因此 X 足够"按**未证明**处理。三条陷阱：① 不要把问题 "WLOG 化" 到特例上（有些变换不保持结构）；
  ② "我采样没找到" ≠ "不存在"，措辞必须是"在我试过的 N 个上达不到"；
  ③ 两条不同公式在样本范围内一致 ⇒ **样本无法裁决**，要裁决必须挑它们分离的点。
  报结论时分开写 **"已证明"**（有清单或穷尽）与 **"采样支持"**。

## 预算与频率的边界

- 单回合会话数与工具调用数有上限；同会话有 4h 与每日上限 —— 触顶时**宁可少发**，
  把余额留给出错告警与真正需要用户的事。
- 唤醒有每小时/每天上限；触顶会静默少唤醒，属预期而非故障。具体数值见
  `bin/config.json` 与 `.future/memory/instance.md`。
