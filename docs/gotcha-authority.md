# 坑 · C · 授权与边界

> **何时读**：拿不准某动作是否越界、或授权口径打架时

（分类 C；来由与真实经过见 `.future/memory/incidents/`，本文件只留判据）

### C1 代答不要越过用户的授权：对外/不可逆那一步要停下来问
- **教训**：早期只授权"代答与推进"时，代答里写了"按常规流程合并"，导致对方真的 push 并合并了 PR——
  可挽回，但确实是未授权的对外动作。
- **现行口径**（以 `POLICY.md` §A.8 / §B 为准）：
  - **允许**让他人：push 自己的功能分支、`gh pr create`、**合并该 PR**（合并前本地检查与 CI 必须
    **实际跑过且全绿**）；但不向主干直推、不 force、不发版/部署。
  - **不得**让他人：发版打 tag、部署上线、换二进制、删除数据、对外发送、承诺。
  - 每一步 push/PR/merge 要记入 `journal/` 与 `reports/on-your-behalf.md`。
- **为什么容易搞反**：授权变过好几轮，旧文档会"看着很对"但已过期——措辞冲突时**以 `POLICY.md` 为准**，
  并顺手把过期的那处改掉。

### C2 一旦对外动作发生，只能由用户决定去留
- **对策**：不擅自 revert（revert 同样是对外且不可逆）；让对方**保持现状**，把
  "留着 / revert / 导出 patch"三选项升级给用户。

### C3 哪些文件属于"本设施自身"
- **已授权**：`POLICY.md`、`bin/config.json`、`prompts/`、`bin/`、`docs/`、`AGENTS.md`、守护进程的
  调度配置都可自行修改
  （走 worktree + PR + CI）——这就是本设施的自我迭代方式。仍受白名单其余各条约束
  （对外发送/发版/删数据/付费）。
- **记录类不经 PR 直接写**：`journal/`、`reports/`（它们不进 git，见
  [privacy-and-state.md](privacy-and-state.md) §4）。

### C4 自动批准不是无差别放行
- **对策**：`bin/approvals.py auto` 带拒绝清单，命中即不批准、转为升级；每轮/每小时有上限；
  逐条记入 `state/approvals.jsonl` 与 `reports/approvals.md`，可审计可推翻。

### C5 一次性指令 ≠ 长期口径
- **教训**：把用户当场的一句"先不要提交 PR"概括成"改名类改动的既定口径"——被当场更正：
  那**只对那一次有效**。把一次性限制当默认，会把可推进的事卡住。
- **对策**：用户**当场**的限制性指令一律 `python3 bin/directives.py add --session <id> --text "…"`，
  有有效期、到期自动失效；`bin/turn_prompt.py` 把未过期指令注入每轮唤醒卡。
  到期仍需执行的，须用户重新确认才写入 `POLICY.md` / `AGENTS.md` 成为长期口径。
- **判断线索**：指令里带"这次""先""等我看"的，几乎一定是一次性的；他若想要长期，会说"以后都…"。

### C6 即时告知制：自主做、事后简报告知
- **适用**：a) 紧急必要但擦边白名单的动作（远端仓库设置等）；b) 影响面超出单会话的改动；
  c) 越权/失误。
- **做法**：**不追加消息打扰**，写 `state/notices.jsonl`（`bin/notice.py add`），由每日简报汇总。
  同一事项只记一条，**必须给出精确回退命令**。
- **改远端仓库设置（含保护规则）已下放为自主**（`POLICY.md` §B.2 例外）：走本制，不再事前请示。

### C7 用户的一句"红线"，口头遵守不算证据——要核**可观测状态**
- **教训**：用户给的一次性指令已明确转达、对方也回话确认"不会自行开 PR"，但它**仍然自己开了 PR 并挂上
  auto-merge**，中间数小时每次唤醒都没有核 PR 状态；若 CI 再绿一次就会不可逆地合进主干。
- **规则**：涉及用户红线的口头遵守不算证据，要核可观测状态——
  - 有没有开 PR：`gh pr list --state all --search "head:<branch>"`，或对该仓 `gh pr list --state open` 扫一眼；
  - PR 会不会自己合：`gh pr view <n> --json autoMergeRequest`——**非空即已挂**，与它嘴上说什么无关；
  - 同类红线：tag/发版（`git tag --list`、`gh release list`）、部署、换二进制（mtime）。
- **频率**：不必每轮全扫，但**每次与"被下过红线指令"的会话交互时顺手核一次**；
  任何"接近收尾 / 开 PR / 发版"的自述出现时**必须核**。
- **处置口径**：发现后**先解除不可逆的那一半**（`--disable-auto`、撤 tag 之前先不删），**再**发消息问原因；
  不要一上来就 close/delete——关闭随时能补，而问清失效点才能防复发。
